# Updates are verified against a signing key built into the app

An update is only installed when its `checksums.txt` carries a valid ed25519 signature from the key whose public half is built into the running app; on macOS the new app must also be signed by the same Apple team. One key signs both release and nightly. Its private half is a GitHub Actions secret used only by the publish jobs. Marasi App is a security researcher's proxy, and the Windows build has no code signature, so without this anyone able to replace a release asset could have every installed app run their binary.

We considered trusting HTTPS from GitHub plus `checksums.txt` alone (the checksums sit beside the binaries, so whoever can swap one can swap both), and a key per channel (both channels are signed by the same CI, so separate keys add no protection). The cost is that the key is very hard to change: to rotate it, ship a release that embeds the new public key and is signed with the old one, then sign everything after it with the new key. An app that skips that release cannot verify later updates and has to be reinstalled by hand. If the private key is lost, every installed app needs a manual reinstall.
