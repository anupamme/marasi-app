# Ledger settings are app defaults with project overrides, stored by the app

Highlight labels and colours, saved queries and the content-type exclusion each have an app-wide value in the marasi-app config YAML and an optional per-project value, and the project value wins. A project follows the app's content-type exclusion until the researcher edits it, with a reset back to following. The per-project values live in the project file, in a client-settings store that Marasi keeps but never interprets: one JSON value per key, keyed by the client's name (`marasi-app`), so changing one saved query or label rewrites only its own key and concurrent writers cannot overwrite each other's keys. The content-type exclusion moves there out of Marasi's own `app.filters` column, because Marasi never applied it and the CLI has no use for it; Marasi instead takes the exclusion as an option on each traffic query.

We considered app-only settings (one engagement's meanings leak into the next and do not travel with a shared project), typed Marasi tables for saved queries and labels (more Marasi surface for things only the GUI uses), and app-side files keyed by project path (lost when a project file moves). The cost of this choice is that another client, such as the CLI, cannot read the app's saved queries without learning its keys.
