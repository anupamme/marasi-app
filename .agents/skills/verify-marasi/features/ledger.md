# Traffic ledger

## Sub-features

- HTTP request/response rows, and WebSocket upgrade rows whose badges column shows the upgrade state
- The WebSocket modal opened from an upgrade: Stream, Checkpoint, Inject, and Connection tabs
- Indexed query search, content-type exclusions, and loading older query pages on scroll
- Request detail in the drawer, notes, highlights, and handoff to Launchpad, Armory, or Logbook

## How to get to it (user POV)

Select the rail item titled `Ledger` or press `Command+2`. The page is the sitemap dock (`.lp-dock`, strip `.lp-strip` labelled with the chosen sitemap node without its scheme, else `Sitemap`, when collapsed; `⌘\` toggles it), a one-row toolbar (`.ledger-toolbar`) with `#searchBox` (placeholder `Search traffic…`), a `Saved queries` button (`#ledgerSavedQueriesButton`), a `Highlights` button (`#ledgerHighlightsButton`), a `Marks` button (`#ledgerMarksButton`) and a `Types` button (`#ledgerTypesButton`, badge `#ledgerTypesHiddenCount` reading `N hidden`) whose menu (`#ledgerTypesMenu`) holds the find box `#ledgerTypesFind`, group chips (`.ledger-types-group`, `data-state` `shown`/`partial`/`hidden`), `#ledgerTypesSource` (`This project's own list` or `Following the app default`) with `#ledgerTypesReset` (`Reset to default`, confirm modal) when the project has its own list, and Shown/Hidden rows (`.ledger-types-row[data-type="…"]`, a checkbox and a pair count; the no-response row has `data-type=""`, reads `(no response)` and is always shown), the windowed table (`.ledger-table`, rows `.ledger-row`, columns `# · badges · Time · Method · Host · Path · Status · Type · Size`), and the status bar (`.ledger-status`: `N in the live view` or `N matching`, `N hidden by type`, `Request N selected` with `Clear`). Only the rows in view are in the DOM.

**Background-job notices.** While a query runs and Marasi's search index is still building, `#ledgerIndexBuilding` (`Search index still building`) sits beside the match count. The drawer header shows `.ledger-prettified-moving` (`Some formatted bodies still moving`) while the `prettified_move` job runs. Both clear without a reload: the app polls `ListJobs` every 2s while a job runs, then reads the Ledger again in place (the sitemap reloads when its job finishes). To see them, rebuild from Settings → Maintenance with enough traffic captured.

The sitemap dock (`.ledger-sitemap`) has a header with `Sitemap` and the host count (`.ledger-sitemap-hosts`, `N hosts`), `Sitemap still building` (`.ledger-sitemap-building`) while Marasi's sitemap job runs, the find box `.ledger-sitemap-find` (filters the loaded hosts and paths), `Collapse all` (`.ledger-sitemap-collapse-all`) and the scope toggle (`.ledger-sitemap-scope`: `All traffic`, `Matching the query`, the second disabled without a running query). Rows are `.ledger-sitemap-node[data-sitemap-node="<node name>"]`: an expand chevron (`aria-label` `Expand <name>`/`Collapse <name>`), the segment (placeholders `{uuid}`, `{int}`, `{hash}` in italics; clicking narrows the query to `sitemap = "<name>"`, again removes it, and the active node has `aria-current="true"`), an eye-off button on hover (`aria-label` `Leave <name> out of the query`, adds `sitemap != "<name>"`), the 5xx count and the pair count (`matching/total` in All traffic with a query; nodes without matches are dimmed). Each level shows its busiest 10 children, then `.ledger-sitemap-more` (`N more` with `Show 50 more`). The strip's search button expands the dock and focuses the find box.

Shortcuts: every menu shortcut for this feature is a catalog action in context `ledger.drawer-closed`, `ledger.drawer-open` and `ledger.drawer-open.websocket` (and, in the WebSocket modal, `websocket` plus `websocket.<tab>`) in `frontend/src/lib/keybindings/catalog.js`; the Marasi menu (`⌘K`) on the page lists them with their current keys. The drawer contexts follow the Ledger store's drawer (`state.ledgerDrawer` in the layout's shortcut state), not Skeleton's drawer.

## Driving it with Chrome CDP

Run `scripts/drive.sh ledger` for route proof; it waits for the toolbar's `Saved queries`, which paints whether the dock is open or collapsed. For capture, send a `text/html` request with a unique path through the isolated proxy (`curl -x http://127.0.0.1:18080 …` to a local disposable server), then wait for that path in the table:

```bash
scripts/drive.sh ledger steps '{"name":"capture","steps":[{"waitText":"/ledger-second"}]}'
```

Pair it with a read-only query: `sqlite3 -readonly <project> "select method, host, path, status_code, content_type from request"`.

Search supports field expressions and boolean operators, not just a table substring filter. A proven sequence:

```json
{"name":"search","steps":[
 {"click":"#searchBox"},{"key":"cmd+a"},
 {"insert":"response_body:\"ledger-second\""},{"key":"enter"},
 {"waitSelector":"#ledgerQueryMatchCount"},{"waitText":"1 match"},{"waitText":"1 matching"},
 {"waitNoText":"/ledger-first"},{"waitText":"/ledger-second"},
 {"click":"[aria-label=\"Clear query\"]"},{"waitText":"/ledger-first"}]}
```

The query stays active across navigation until cleared, so the recipe clears it; otherwise later recipes cannot find rows the query excludes.

Enter runs the query at once. Typing alone runs it after a 700 ms debounce. `#ledgerQueryMatchCount` reads `1 match`, `N matches`, or `N+ matches` while older pages remain. The query-help toggle describes the supported fields, operators, and examples.

The query box is a one-line CodeMirror editor; `#searchBox` is its `.cm-content`, so `click`, `cmd+a` and `insert` work as on an input. It offers suggestions in `.cm-tooltip-autocomplete`: fields by prefix while typing a word (including `highlight`, `sitemap`, `finding`, `test_case`, `length` and `metadata.`), a field's operators after `<field> `, and example values after the operator (`*` after `highlight:`, `note:`, `launchpad:`, `finding:`, `test_case:` and `metadata.<key>:`). `Ctrl-Space` opens them on request. Enter picks the selected suggestion while the list is open and runs the query otherwise; a finished value or word offers nothing, so Enter after an inserted query runs it. Pick with `{"click":".cm-tooltip-autocomplete li","hasText":"<label>"}` or `down` and `enter`. Escape closes an open list, then clears the query. An invalid query shows its message in `#ledgerQueryError` (`role="alert"`) in place of the match count and underlines the word at Marasi's position (`.ledger-query-error`). Bare text searches the request, response, note, and metadata, and needs at least three characters; punctuation can require quoting.

For handoff, click a row with `{"click":".ledger-row","hasText":"<path>"}`, wait for `.ledger-drawer` (below the table, request and response side by side), then use the drawer's shortcuts. For example, `cmd+l` sends the selection to a new launchpad and shows `Sent 1 request to a new launchpad` (`Sent N requests …` for several; the launchpad is named `Request N` or `N requests`) with a `Jump to Launchpad` action. `cmd+shift+e` maximises the drawer over the table (`.ledger-table` leaves the DOM) and restores it; `cmd+shift+]`/`[` move the selection; `escape`, the status bar's `Clear`, or the drawer's `Close the drawer` button closes it. Drag `.ledger-drawer-resize` to resize it: `{"drag":".ledger-drawer-resize","to":".ledger-row","toHasText":"<path near the top>"}` (prove it with the drawer's height before and after). The selection, the drawer's height and maximised state, and the dock's width and collapsed state survive leaving and returning to the Ledger, so close the drawer at the end of a recipe.

**Selection and the row menu.** Pressing a row selects it alone; dragging across rows sweeps them; `⌘`-click toggles, `⇧`-click selects from the anchor, `⌘⇧`-click adds that range. Drive them with `"modifiers"` on a click (`{"click":".ledger-row","hasText":"/b","modifiers":["shift"]}`, `["cmd"]`) and the sweep with a `drag` step (`{"drag":".ledger-row","hasText":"/a","to":".ledger-row","toHasText":"/c"}`). With the table focused, `⇧↓`/`⇧↑` extend from the anchor (the driver sends `shift+down`; it has no up arrow), `cmd+a` selects the whole query or live view as a Marasi selection (query, exclusion and the results' as_of, never ids; every loaded row up to that as_of shows selected, later new matches do not), and `escape` clears. Selected rows carry `aria-selected="true"`; the focused one, which the drawer shows, is outlined. The status bar reads `Request N selected`, `N selected`, or after `cmd+a` `All N matching selected`, plus ` · M new matches not included` once new matches arrive (`#ledgerSelectionCount`). Right-click a row (`{"click":".ledger-row","hasText":"<path>","button":"right"}`; a selected row keeps the selection) or press `cmd+.` to open `.ledger-row-menu`: a header summing up the selection, a `Type an action…` filter (`.ledger-row-menu-filter`, which searches submenus too), then items `[data-menu-item=<id>]` (`open`, `websocket`, `launchpad`, `armory`, `finding`, `testcase`, `note`, `highlight`, `copy`, `narrow`, `select`, `metadata`, `delete`). The `launchpad` submenu ends with a `Remove from launchpad` heading listing every launchpad (`[data-menu-item=lpu-<id>]`). With several pairs, `note` is a submenu: `n-append` (`Append a note…`, a prompt modal) and `n-clear` (`Clear notes…`). `delete` (`Delete from project…` / `Delete N from project…`) and `n-clear` open the confirm modal naming the count (Delete warns `… evidence in a finding.` when any pair is); nothing changes until it is confirmed. After `cmd+a` over more rows than are loaded, `armory`, `copy`, `lp-each`, `f-new` and `t-new` are disabled (`Not for all matching`), their shortcuts (`⌘⇧A`, `⌘⇧F`, `⌘⇧T`, the copy keys) only toast `Not for all matching`, and the header reads `All N matching` without the host, method and status breakdown. `select` lists `s-highlight-<n>` for each highlight among the selected pairs (`All with this highlight`, or `All with highlight <label>` when there are several). Bulk changes run once on the selection and toast Marasi's count (`Added 3 requests to "…"`, `Removed 1 request from "…"`, `Appended a note to 2 requests`, `Cleared 2 notes`, `Deleted 2 requests`); the rows are read again in place. The `highlight` item is a row of swatches (`.ledger-highlight-swatches`, buttons `[data-menu-item=h-1]` to `h-8` and `h-none`, `role=menuitemradio`, `aria-checked` `true`/`mixed`/`false`); hovering one shows its label at the row's end, and with the row active `arrowleft`/`arrowright` pick a swatch and `enter` applies it. Typing a label in the filter lists the swatch as `Highlight › <label>`. Applying one toasts Marasi's count (`Highlighted 2 requests "Red"`, `Cleared the highlight on 1 request`) and repaints the rows' 3px stripe and tint in place. Submenus open in `.ledger-row-submenu`. Keys: arrows move, `arrowright`/`enter` open a submenu, `arrowleft` goes back, `enter` runs, `escape` closes. Each change reports through a toast (`Linked 2 requests to finding "…"` with the count Marasi changed, `Selected N requests`, `Narrowed the query: …`, `Copied 2 URLs`). Shortcuts with a selection: `⌘L` new launchpad, `⌘⇧A` Armory, `⌘⇧F` new finding, `⌘⇧T` new test case, `⌘N` note, `⌘⇧C` copy URLs, `⌘M` metadata, `⌘.` the menu.

## WebSocket streams

A WebSocket message is the whole message, however many frames it arrived in. UI text says "message"; action ids keep `frame` (`websocket.stream.next-frame`, `websocket.checkpoint.forward-frame`, `websocket.inject.inject-frame`).

Drive a WebSocket through the proxy with a raw-socket client: send an absolute-form upgrade (`GET http://127.0.0.1:<port>/<path> HTTP/1.1` with `Upgrade: websocket`, `Connection: Upgrade`, `Sec-WebSocket-Key`, `Sec-WebSocket-Version: 13`) to `127.0.0.1:18080`, then read and write masked frames. Use a disposable local server you control, so each state below is a deliberate server behaviour. Offer `Sec-WebSocket-Extensions: permessage-deflate` to get a deflate connection; add another offer (for example `x-webkit-deflate-frame`) to see it stripped.

**Upgrade states.** The badges column shows a WebSocket icon (its label is the badge's `title` and `aria-label`; past three badges, hover the `+N` slot `.ledger-badges-more` for the full list) whose state comes from `frontend/src/lib/websocket/presentation.js`:

| `websocket.state` | Icon | Opens a stream | How to produce it |
| --- | --- | --- | --- |
| `pending` | warning | yes | Hold the server's 101 response |
| `open` | success | yes | Complete the handshake |
| `closed` (or no state) | error | yes | Close the connection from either side |
| `failed` | error, slashed; tooltip `WebSocket handshake failed — see the logs on Home` | no | Offer `permessage-deflate` and have the server answer an extension response that matches no offer (for example `permessage-deflate; server_max_window_bits=20`, or two extensions). Home's logs get `WebSocket handshake failed: …` |
| `dropped` | neutral, slashed; tooltip `Upgrade response dropped` | no | Drop the 101 response in Checkpoint (see [checkpoint.md](checkpoint.md)) |

A failed or dropped upgrade reaches the Ledger live through `ws-state`, with no reload. A slashed row has no drawer `WebSocket` button, and `ledger.drawer-open.websocket` is ineligible, so `⌘⇧O` stays the drawer's `Open Request`. Prove the tooltip with `[title="Upgrade response dropped"]` or the failed text.

**Opening the modal.** Open the upgrade row's drawer and click its `WebSocket` button, or press `Open WebSocket Stream` (`⌘⇧O`; it closes the modal again on every tab but Inject, which binds `⌘⇧O` itself). The header shows `<transport>://<host><path>`, `N messages`, and `Close Connection` (`⌘⇧X`, toast `WebSocket connection closed`, disabled unless the state is open). Tabs, in `⌘[`/`⌘]` order: `Stream`, `Checkpoint`, `Inject`, `Connection`. Each tab's context is `websocket.stream`, `websocket.checkpoint`, `websocket.inject`, or `websocket.connection`; the Connection tab binds no actions of its own.

**Progress chip.** While a message is still arriving, the header shows `↓ receiving <size> · <n> frames` (`↑` for client to server), titled `A message is still arriving; it appears in Stream once its last frame is in`. Produce it with a fragmented message whose frames arrive more than 100 ms apart (Marasi emits progress at most every 100 ms): send a text frame with FIN clear, then continuations a second apart, then the final frame. The chip clears when the message lands in Stream, or when Checkpoint holds it.

**Stream.** Selecting a row shows the properties grid above the payload: `Type`, `Direction` (`client → server`/`server → client`, plus `(sent by Marasi)` on Marasi's own closes), `Size`, `Frames`, `Compressed` (`yes`/`no`), `Flags`, and a `Note` when the payload shown is not the message. Buttons: `Metadata`/`View Message` (`⌘⇧M`) and `Copy to Inject` (`⌘⇧I`, toast `Copied to Inject`). Flags, their row edge, and how to produce them:

| Flag | Edge | Produce it |
| --- | --- | --- |
| `Proxy` | warning | Any close Marasi sends, for example after `Too large` |
| `Too large` | error | Add `websocket_max_message_size: 1024` to `marasi_config.yaml` in the isolated config directory, run `scripts/restart.sh`, then send a 2 KB message. Marasi closes with 1009 to the sender and 1001 to the receiver; `Size` reads `> <size seen>` |
| `Corrupt` | error | On a deflate connection, send an RSV1 frame whose payload is not valid deflate (close 1007) |
| `Cut short` | error | Start a fragmented message and drop the TCP connection before its final frame |
| `Bad close` | error | Send a close frame with an invalid code or a 1-byte payload |
| `Dropped` | strike-through, no edge | Drop it in the Checkpoint tab |
| `Injected` | tertiary text | Inject it from the Inject tab |

Hover a row to read `<label>: <flag tooltip>` lines; a forwarded interception reads `Forwarded intercepted message`.

**Inject.** `Direction` (`Client to server`/`Server to client`, `⌘⇧D`), `Opcode` (`Text`, `Binary`, `Close`, `Ping`, `Pong`, `⌘⇧O`), and `Inject` (`⌘⇧Enter`, toast `WebSocket message injected`) beside a `Connection Open`/`Connection Closed` chip. On a deflate connection with `Text` or `Binary`, a `Send uncompressed` checkbox appears under the toolbar. Prove both choices: inject once with it clear and once checked, then check the injected rows' `Compressed` reads `yes` and `no`.

**Connection.** Read-only: `URL`, `State` chip, `Close` (`<code> <reason>`, with `— closed by Marasi` in warning colour when any stored message is a Marasi close), a `Compression` section (`Extension` `permessage-deflate` with client/server context takeover and max window rows, `none negotiated`, or `not recorded` without a connection record), and `Stripped by Marasi` with one `Offer` row per stripped extension or `none`.

## Gotchas

- `#searchBox` is always in the toolbar. The Types menu mounts only while open: open it with `{"click":"#ledgerTypesButton"}` (its text includes the hidden badge, so `{"text":"Types"}` fails) or `⌘⇧F`, which also focuses `#ledgerTypesFind`; typing a full type or `major/*` there and pressing Enter (or clicking `#ledgerTypesAdd`) hides it. A click outside the menu closes it (click `.ledger-status`, not the table, which would select a row); Esc closes it only while focus is inside the menu, so after clicking a row in it, close it with a click on `.ledger-status`. This holds for every toolbar menu. `⌘P` toggles the query fields panel; `⌘⇧S` focuses `#searchBox` (pressing it again blurs the box). `⌘]`/`⌘[` scroll the table a page.
- The `Saved queries` menu (`{"click":"#ledgerSavedQueriesButton"}`; its badge is the active saved query's name) opens `#ledgerSavedQueriesPanel` with groups `This project`, `All projects` and `Built-in` (the six built-ins from the spec; empty groups are left out) of `.ledger-saved-query` rows, each with a match count read with `CountTraffic` after the panel opens (`…` while loading, `!` for a query Marasi rejects). Click a row's name to replace the query in `#searchBox` and run it; clicking the active one clears it. `#ledgerSaveQuery` (`Save current query`) is enabled only for a valid, already-run query no visible saved query has; it shows `#ledgerSavedQueryName`, the checkbox `#ledgerSavedQueryKeepForAll` (`Keep for all projects`, off by default: the query goes to `This project`) and Save. Hovering a row shows `button[aria-label="Rename <name>"]`, `button[aria-label="Delete <name>"]` (confirm modal; a project query's reads `from this project`) and `button[aria-label="Move <name> to all projects"]` or `button[aria-label="Move <name> to this project"]` for saved queries, or `button[aria-label="Hide <name>"]` for built-ins; `#ledgerShowHiddenBuiltins` (`Show N hidden built-ins`) lists hidden ones with `Show <name>`. A query equal to a hidden built-in still badges its name and can't be saved again. Changes show at once and are put back, with an error toast, if the write fails. App-wide queries persist to `saved_queries` and hidden ids to `hidden_builtin_queries` in `marasi_appconfig.yaml`; prove persistence with `restart.sh`. Project queries are rows in the project file: `sqlite3 -readonly <project> "select key, value from client_setting where client = 'marasi-app' and key like 'ledger.saved_query.%'"`; a move leaves exactly one copy across the YAML and that table.
- The `Marks` menu (`{"click":"#ledgerMarksButton"}`; its text includes the active-mark badge) opens `#ledgerMarksPanel` with one `.ledger-mark` row per mark, each with a `data-term` (`note:*`, `finding:*`, `test_case:*`, `launchpad:*`, `metadata.intercepted = true`) and a `.ledger-mark-count` read with `CountTraffic` on each opening (`…` while loading, `–` on failure). Click a row (`{"click":".ledger-mark","hasText":"Has note"}`) to toggle its term in `#searchBox` and run the query at once; the panel stays open and the row gets `aria-checked="true"`. Esc or a click outside closes it.
- The `Highlights` menu (`{"click":"#ledgerHighlightsButton"}`; badge = highlight terms in the query) opens `#ledgerHighlightsPanel`: `Any highlight` (`highlight:*`) and one `.ledger-highlight` row per highlight (`data-term` `highlight = N`) with swatch, label, scope tag (`project`/`app`) and `.ledger-highlight-count`. Clicking a highlight row toggles its term like Marks, 250 ms after the click so a double-click only renames. The pencil (`.ledger-highlight-rename-button`, shown on hover) or a double-click opens `.ledger-highlight-rename` with a label input and a `Use in all projects` checkbox; Enter saves (unticked: the project's `ledger.highlight.<n>`; ticked: the app label, dropping the project's), Esc cancels.
- On project open, a project with old hex highlights (`metadata.highlight`) is migrated once in the background; the toolbar shows `#ledgerHighlightMigration` (`Updating old highlights…`) meanwhile, then the table reloads. The project's client setting `ledger.highlight_migrated` records it. Marasi has one database connection, so the migration and the project's other opening reads queue behind each other: on the 100k fixture it finished while the page still showed `Loading <project>…` (about 50 s), and the notice never painted. Prove the migration in SQLite instead: `ledger.highlight_migrated` is `true`, `select count(*) from request where json_extract(metadata,'$.highlight') is not null` is 0, and `pair_highlight` holds each mapped number (`#EF4444`→1, `#EAB308`→3, `#22C55E`→4, `#3B82F6`→6, `#A855F7`→7; a pair that already had a number keeps it). Open an APFS clone (`cp -c`) of the fixture for each attempt: the flag makes later opens skip it.
- Clicking anywhere in `.ledger-table` selects the row under the pointer and opens the drawer, which swaps the shortcut context to `ledger.drawer-open` (`⌘⇧F` then creates a finding).
- The content-type exclusion hides matching types. The app default (Settings → Content Types, table `#settingsDefaultContentTypes`) already hides images, fonts, media, JavaScript, CSS, PDF, archives, and office types. Use `text/html` for capture proof. They include `application/octet-stream`, which `python3 -m http.server` sends for extensionless paths, so serve a `.html` path.
- An empty Ledger only proves navigation. Complete capture proof needs traffic through the proxy.
- HTTPS traffic needs the verification instance's generated certificate.
- Search and filters can hide newly captured rows; record their values in evidence.
- The live view batches `request`/`response` events and flushes every 200 ms. The table lists the live view and query results newest first by default. Every header but badges sorts: `button[data-sort="<field>"][title="Sort by …"]` (`#` and `Time` share `requested_at`, so pick `[title="Sort by time"]`); a click sorts, a second reverses, and the sorted header has `aria-sort` `ascending`/`descending` and an arrow. Pairs without a response sort last both ways and show `…` dimmed in Status (Marasi stores status `-1` for them). In the newest-first live view new traffic lands on top; scrolled down, the rows stay put and a `N new` button returns to the top. During a query (or any other sort) matching traffic waits behind `1 new match · Show` or `N new matches · Show`, which appears once traffic pauses for 500 ms (at most 3 s after the first new pair under steady traffic); `Show` reads the results again in place. A `cmd+a` selection then reads `All N matching selected · M new matches not included`.
- An exclusion value is an exact type or a whole major type (`image/*`); the Images, Fonts, Audio and Video chips store `major/*`. A type hidden through `major/*` has a disabled checkbox. Inspect the Types menu rather than assuming defaults: editing it gives the project its own list, which no longer follows Settings.
- Replacing the query text: `cmd+a` right after clicking `#searchBox` sometimes loses to the click's caret, so `insert` appends. Clear first with `{"click":"[aria-label=\"Clear query\"]"}`, or press `escape` twice in the box (close suggestions, then clear), then click and insert.
- Saved queries: the row actions (Rename, Move, Delete, Hide, and `Show <name>` in the hidden list) only show on hover; reach them with a `hover` step on the row first (`{"hover":".ledger-saved-query","hasText":"<name>"}`). A rename commits on Enter. Delete's confirm button is `Confirm`; the Types menu's `Reset to default` confirm is `Confirm` too.
- Highlights menu: rename with `{"hover":".ledger-highlight","hasText":"<label>"}` then the pencil, or `{"click":".ledger-highlight button[title=\"highlight = N\"]","clickCount":2}`. The input is `input[aria-label="Label for highlight N"]`; save with `.ledger-highlight-rename button[aria-label=Save]` (Enter after an `insert` did not always submit) and tick `.ledger-highlight-rename input[type=checkbox]` for `Use in all projects`.
- Sitemap: `button[aria-label="Expand <node>"]` opens a node (origins are `https://host`); a node's own button has `title="Narrow the query to sitemap = …"`. The strip's buttons are `button[title="Show the sitemap"]` and `button[title="Search the sitemap"]`. In `Matching the query`, open levels read again one by one: wait until a child's All-traffic total (for example `4,654`) is gone before a screenshot. `Sitemap still building` reflects the last sitemap read, so after a Rebuild it shows on the next read (switch scope or change the query), not by itself.
- Large-project timing (100k fixture, Apple M2): the first rows paint at once; Matching-mode reads and saved-query counts take 1–5 s; rebuilding the search index takes over 30 minutes for `traffic_index` alone, and while it runs text queries match nothing yet (`0 matching` with `Search index still building`). Rebuild the sitemap (about 1 minute) rather than the index when you only need a notice.
- Delete confirmation: the modal names the count and, when any pair is evidence in a finding, adds `N of them are evidence in a finding.` after the links finish loading; wait for that text before a screenshot. Confirm with `{"text":"Delete","within":".modal-footer"}`.
